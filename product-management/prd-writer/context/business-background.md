# 企业级软件 PRD 的典型背景

本文档帮助 prd-writer 理解 B2B / 企业级软件的常见业务背景。仅在用户提供的输入不足时按需引用。

---

## 典型客户类型

| 类型 | 特征 | PRD 重点 |
|---|---|---|
| **离散制造**（机械/汽车/电子）| 多 BOM、多工序、强追溯 | 物料主数据、工艺路线、质量记录 |
| **流程制造**（化工/医药/食品）| 配方为主、连续工序、合规要求高 | 批次管理、配方版本、合规审计 |
| **零售/快消** | 高 SKU、门店多、价促复杂 | 商品中心、价格策略、门店运营 |
| **工程建设**（EPC/施工）| 项目制、合同复杂、长周期 | 项目结构、综合单价、进度款 |
| **集团/多公司主体** | 法人多、汇总报表、合并抵消 | 主体隔离、合并规则、跨主体协作 |

PRD 起草时若客户类型未明确，**Step 1 必含一题"客户行业偏向"**，否则示例与品类细分会泛化失焦。

## 典型模块

### SRM（Supplier Relationship Management，供应商关系管理）

| 子模块 | 核心业务 |
|---|---|
| 供应商主数据 | 供应商准入、资质审核、分类分级 |
| 寻源管理 | 寻源单、供应商邀请、寻源发布 |
| **报价管理** | 报价模板、供应商响应、比价分析 |
| 合同管理 | 合同生成、续签、变更 |
| 采购订单 | PO 创建、收货、对账 |

### ERP（Enterprise Resource Planning）

涵盖财务、库存、销售、采购、生产、人力等。模块分工：FI（财务）、CO（控制）、SD（销售分销）、MM（物料管理）、PP（生产计划）等。

### MES（Manufacturing Execution System，制造执行系统）

车间执行层，含工单管理、报工、质检、设备管理、WIP 追溯。

### WMS（Warehouse Management System，仓储管理系统）

含入库、上架、拣货、出库、盘点、移库。

### CRM（Customer Relationship Management）

含客户主数据、商机、报价、合同、售后服务。

## 典型用户角色

| 角色 | 在系统内的典型行为 |
|---|---|
| **业务专家 / CoE**（卓越中心）| 配置型用户。设计模板、字典、流程；要求"零代码自助" |
| **业务执行人员**（采购员/销售员/仓管员）| 日常高频使用；要求操作简单快速 |
| **审批主管 / 经理** | 中频审阅；要求看到关键摘要而非细节 |
| **外部用户**（供应商/客户/合作伙伴）| 通过门户/小程序参与；要求体验一致、入口清晰 |
| **系统管理员 / IT** | 权限分配、字典维护；**不参与业务配置**（现代 SaaS 的核心边界）|
| **合规审计** | 看操作日志、追溯记录 |

## 典型业务约束

### 多租户（Multi-tenancy）

绝大多数 B2B SaaS 是多租户架构。PRD 不必详写多租户机制，但需注意：
- 所有业务实体都有"租户"边界
- 名称唯一性、字典维护等都以租户为隔离单位
- 跨租户访问默认禁止

### 数据隔离层级

- 租户级（最常见）
- 公司主体级（集团客户场景）
- 部门级 / 项目级（更细粒度）
- 角色级（基于角色的可见性）

### 版本控制

企业级软件的**配置型实体**（模板、价目表、流程定义）通常需要：
- 不可变版本快照（一旦被业务使用就不能改）
- 启用/停用日期
- 多版本共存

PRD §4 业务实体描述这类对象时要明确"是否有版本"。

## 典型业务流程模式

### 单据流转模式

```
草稿 → 提交 → 审批 → 已生效 → 执行中 → 完成 / 取消
```

变体：
- 含多级审批
- 含会签 / 并签
- 含驳回回退

### 配置 / 引用模式

```
配置模板（草稿 → 已发布）
   ↓
业务单据引用某版本模板（不可变快照）
   ↓
模板停用不影响已引用单据
```

### 主数据 / 业务数据模式

```
主数据（供应商、物料、客户等）：长期稳定，少变更
   ↓
业务数据（订单、报价、单据等）：高频产生，引用主数据
```

业务数据引用主数据时通常**只引用 ID，不冗余数据**；但快照型场景（如下单时锁定价格）会冗余关键字段。

## 通用合规与审计

很多 B2B 软件需要满足合规要求：
- **操作日志**：记录关键操作（创建/修改/删除/审批/导出）
- **数据保留期**：5 年、7 年、10 年 不等
- **审批留痕**：审批人、审批时间、审批意见不可篡改
- **数据导出审计**：谁在什么时候导出了什么数据

PRD §4 业务实体可不写这些细节，但 §6.2 范围外应明示"是否纳入本期"。

## 与 AI 能力的整合模式

| 模式 | 示例 | PRD 表达 |
|---|---|---|
| **辅助决策** | 智能推荐、相似匹配、异常预警 | AI 作为可选能力嵌入主流程；不强制采纳 |
| **自动生成** | 报告生成、文档摘要、模板推荐 | AI 输出物可被用户编辑 |
| **结构化提取** | OCR、文档解析 | 提取结果由用户复核 |
| **对话式交互** | 智能客服、AI 助手 | 单独的 AI Spec 而非 PRD |

PRD 涉及 AI 能力时通常**作为辅助层**，主流程仍为传统业务流程。**AI 决策不应替代人工**，除非业务方明确接受。
