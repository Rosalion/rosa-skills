# 术语表

本文件存放 prd-writer 起草 PRD 时涉及的术语。

**使用原则**：
- **第 1 节**：PRD 撰写本身的最基本术语（FR / 子模块 / P0 等）。这些是 skill 工作流必备词汇，固定保留
- **第 2 节**：**业务术语示例**（以 SRM 为参考）。实际起草时根据用户的领域临时增补
- **第 3 节**：使用过程中遇到用户给出新术语或澄清旧术语时，**按需追加到本文件**作为后续起草的参考

---

## 1. PRD 撰写基本术语

### 文档体系

| 术语 | 定义 |
|---|---|
| **PRD**（Product Requirements Document）| 产品需求文档。**业务契约层**：描述"做什么、为什么、做到哪里"。本 skill 的产出 |
| **FS**（Functional Spec）| 功能规格书。**实现契约层**：描述"怎么做"。由下游 fs-writer 派生 |

### 需求层级

| 术语 | 定义 |
|---|---|
| **模块**（Module）| 系统的一级划分；**一个模块对应一份 PRD** |
| **子模块**（Sub-module）| 模块内的二级划分（§5.1 / §5.2 / ...）；简单模块只有一个子模块，复杂模块拆出多个 |
| **功能点 / FR**（Functional Requirement）| 子模块下最小可独立交付的功能单元；本质上也是 User Story（但不强制 As-I want-So that 句式）|

### 编号与优先级

| 术语 | 定义 |
|---|---|
| **FR-N.M** | 功能点编号，多级数字（FR-1.1、FR-1.2、FR-2.1），前缀对应 §5.N 子模块号 |
| **OQ-NNN** | 待决问题编号（§7 可选） |
| **P0** | 本期必须实现 |
| **P1** | 本期推荐实现 |
| **P2** | 设计意图保留，本期不实现；FS 仅需 schema 预留扩展位 |

### 撰写阶段

| 术语 | 定义 |
|---|---|
| **Step 0 输入识别** | 读取用户提供的输入，识别 PRD 覆盖范围 |
| **Step 1 P0/P1 澄清** | 一批问题，P0 必答 / P1 带默认值，限 8 个 |
| **Step 2 v0.1 业务意图** | 起草 §1~§4（摘要、上下文、流程、实体）|
| **Step 3 v1.0 完整版** | 起草 §5~§6（功能点、范围）|
| **Step 4 可选章节** | 询问是否追加 §7 OQ / §8 备注 |

## 2. 业务术语示例（SRM 领域）

> 本节仅以 SRM 为示例。实际起草其他领域（ERP / WMS / MES / CRM 等）的 PRD 时，**临时补充对应领域的术语**。

| 术语 | 含义 |
|---|---|
| **寻源**（Sourcing）| 采购方寻找合适供应商的过程；含 RFI / RFP / RFQ 等子动作 |
| **RFI / RFP / RFQ** | Request for Information / Proposal / Quotation；按信息深度递进 |
| **询价 / 比价 / 定标** | 邀请供应商报价 → 多方报价对比 → 选定中标供应商 |
| **报价底稿** | 采购方为供应商预生成的报价表单；供应商在底稿上填值 |
| **框架协议 / 长协** | 与供应商约定一段时间内的价格与数量条款 |
| **阶梯价** | 按采购数量分档定价 |
| **BOM** | 物料清单 |
| **MOQ** | 最小起订量 |
| **含税价 / 不含税价** | 含税价 = 不含税价 × (1 + 税率) |
| **未清订单** | 已下单但未完成的订单 |

## 3. 用户领域术语（按需追加）

> 起草过程中如遇到用户提供的新术语或对旧术语的澄清，**按以下格式追加**：

```
### <领域名>

| 术语 | 含义 | 来源 |
|---|---|---|
| <术语> | <含义> | <用户/客户/会议纪要等> |
```

示例（当用户起草 WMS 项目时）：

```
### WMS

| 术语 | 含义 | 来源 |
|---|---|---|
| 打托 | 将多件物料组合到一个托盘上并贴标签的动作 | 客户访谈 2026-03 |
| 上架 | 将物料按规则放入仓库货位 | 行业通用 |
```

## 边界澄清

- **PRD 不写字段**：业务实体只描述概念，不写字段名/类型/长度。字段定义归 FS §6
- **PRD 不写状态机细节**：可在业务规则里简略描述（如"草稿→已发布→已停用单向不可逆"）；详细状态机由 FS 承载
- **PRD 不写界面原型**：界面留给 FS §3 功能界面
