# 示例 2：Step 1 P0/P1 澄清问题（一批）

> 展示 prd-writer Step 1 的实际产出形态。

---

**场景**：客户提出"想做一个供应商报价模块"。PM 在起草前用 prd-writer，skill 在 Step 1 抛出以下澄清问题：

---

```
🔴 P0 — 必答（阻塞起草）

【模块边界】
1. 本模块的上下游边界：
   - 上游：寻源单是否由本模块创建？(A) 是 / (B) 否，由其他寻源模块创建
   - 下游：定标后的合同生成是否在本期？(A) 是 / (B) 否

【核心能力】
2. 报价格式是否需要支持以下三类：
   - 标准物料（单价×数量）：是 / 否
   - 服务/工程类（多构成项）：是 / 否
   - 框架协议（阶梯价/年度价）：是 / 否

【AI 能力】
3. 本期是否纳入 AI 辅助比价：
   (A) 不纳入
   (B) 纳入，作为辅助（推荐）
   (C) 纳入，作为核心卖点

【范围排除】
4. 以下功能是否在本期范围内？逐项标注"做 / 不做"：
   A. 多币种汇率换算
   B. 招投标流程（公开招标 / 邀请招标 / 密封多轮）
   C. 异常价格识别
   D. 报价单 OCR 解析
   E. 跨企业供应商价格情报
   F. 多公司主体数据隔离
   G. AI 谈判策略建议


🟡 P1 — 可推进（不答按默认）

【客户行业偏向】
5. 目标客户行业偏向？— 默认：多行业通用
   选项：(A) 离散制造 / (B) 流程制造 / (C) 工程建设 / (D) 多行业通用

【模板配置粒度】
6. 报价模板的可配置粒度？— 默认：表头字段控制 + 三种行类型选择
   选项：详见后续业务规则讨论

【供应商响应方式】
7. 供应商响应方式？— 默认：供应商门户登录
   选项：(A) 门户登录 / (B) 邮件链接临时填写 / (C) 仅采购员代填

【数据保留期】
8. 比价过程留痕保留期？— 默认：与寻源单生命周期一致
```

---

## 关键示范点

1. **P0/P1 分组明确**：P0 4 题、P1 4 题，**总数 8 题**符合上限
2. **P0 题均为多选式**：用户可在 30 秒内点选；不必发散性回答
3. **P1 题均带具名默认值**：用户不答也能继续推进
4. **必含范围排除题**（第 4 题）：列 7 项让用户标注，是避免范围蔓延的核心
5. **按主题分组**：模块边界 / 核心能力 / AI / 范围 / 客户行业 / 模板 / 响应 / 保留期；用户视觉清晰
