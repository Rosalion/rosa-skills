# 业务背景

本文件存放与领域开发相关的业务背景描述，帮助 fs-writer 在 PRD 提供的信息不足时补充常识。

**使用原则**：
- 本文件**仅以 SRM 为示例骨架**，展示业务背景的组织形式
- 实际起草 FS 时，**根据 PRD 所属领域**（如 ERP / WMS / MES / CRM / 行业 SaaS 等）**临时补充对应领域的背景知识**
- 如果 PRD 属于 SRM 领域，本文件可直接引用
- 如果 PRD 属于其他领域，本文件仅作"业务背景应包含哪些维度"的格式参考

---

## 示例：SRM 业务背景

### 1. 客户是谁

SRM（Supplier Relationship Management，供应商关系管理）系统的典型客户：

| 客户类型 | 业务特征 | 关注重点 |
|---|---|---|
| **离散制造**（机械 / 汽车 / 电子）| 多 BOM、外协加工多、原材料种类繁杂 | 标准物料询比价、供应商分级、价格历史 |
| **流程制造**（化工 / 医药 / 食品）| 大宗原料、批次管理、合规要求高 | 长期协议价、质量参数、批次追溯 |
| **工程建设**（EPC / 施工）| 项目制、综合单价、分项报价 | 分项明细报价、阶段付款、变更管理 |
| **零售 / 快消** | 高 SKU、门店多、价促复杂 | 框架协议、阶梯价、年度返点 |
| **集团 / 多公司主体** | 法人多、采购规模大、需汇总 | 主体隔离、合并采购、跨主体结算 |

### 2. 行业专业术语

| 术语 | 含义 |
|---|---|
| **寻源**（Sourcing）| 采购方寻找合适供应商的过程；含 RFI / RFP / RFQ 等子动作 |
| **RFI / RFP / RFQ** | Request for Information / Proposal / Quotation；按信息深度递进 |
| **询价 / 比价 / 定标** | 邀请供应商报价 → 多方报价对比 → 选定中标供应商 |
| **报价底稿** | 采购方为供应商预生成的报价表单；供应商在底稿上填值（vs 供应商自己填空白单）|
| **框架协议 / 长协**（Frame Agreement）| 与供应商约定一段时间内的价格与数量条款，期间下单按此协议执行 |
| **阶梯价** | 按采购数量分档定价（如 1-99 件 100 元，100+ 件 90 元）|
| **BOM**（Bill of Materials）| 物料清单，描述一个产品由哪些原料/零件构成 |
| **MOQ**（Minimum Order Quantity）| 最小起订量 |
| **税率 / 含税价 / 不含税价** | 含税价 = 不含税价 × (1 + 税率)，发票相关概念 |
| **未清订单** | 已下单但未完成（未交货或未对账）的订单 |
| **供应商分级** | A / B / C 级分类，影响是否优先邀请、付款条件等 |

### 3. 常见约定

#### 多租户与数据隔离

- B2B SaaS 默认多租户；所有业务实体表都含 `tenant_id` 字段
- 同一租户内可能再分多个公司主体（集团客户）
- 跨租户访问默认禁止；跨主体根据集团权限策略
- 唯一性约束（如模板名称）通常带租户前缀：`UNIQUE (tenant_id, name)`

#### 版本控制（配置型实体）

很多 SRM 配置（模板、价目表、流程定义）需要：
- **不可变版本快照**：表中典型字段 `version_no` / `snapshot` / `published_at`；快照写入后永不更新
- **启用 / 停用日期**：`effective_from` / `effective_until`；通过定时任务扫描自动激活/退役
- **多版本共存**：新版本不影响已引用旧版本的进行中业务

#### 主数据 vs 业务数据

- **主数据**：供应商、物料、客户、组织 — 长期稳定
- **业务数据**：订单、报价、单据 — 高频产生
- **快照引用**：业务单据生成时通常**复制关键字段**而非仅引用 ID（如下单时锁定价格、规格、商品名），避免主数据后续变更影响历史业务

#### 单据状态机

SRM 单据普遍遵循：
```
草稿 → 提交 → 审批 → 已生效 → 执行中 → 完成 / 取消
```

**状态字段约定**：
- 字段名：`status`
- 数据类型：CHAR(20)
- 取值参考独立的状态字典表（避免硬编码）

#### 字段命名约定

| 中文 | 英文 |
|---|---|
| 编号 / ID | `id`、`<entity>_id` |
| 名称 | `name` |
| 状态 | `status` |
| 类型 | `type`、`<entity>_type` |
| 是否启用 / 隐藏 / 必填 | `is_enabled` / `is_hidden` / `is_required` |
| 创建时间 / 创建人 | `create_time` / `create_user` |
| 更新时间 / 更新人 | `update_time` / `update_user` |
| 备注 | `remark` / `description` |
| 排序顺序 | `sort_order` |
| 父对象 ID | `parent_id`、`<parent_entity>_id` |
| 快照内容 | `snapshot` |

英文命名遵循 snake_case；业务命名遵循中文。

#### 通用表字段

绝大多数 B2B 业务表含以下通用字段：

- `id`（CHAR / BIGINT 20，主键）
- `tenant_id`（CHAR 20，多租户隔离）
- 审计四件套：`create_time` / `create_user` / `update_time` / `update_user`

FS §6 数据表结构可在通用约定中统一声明、表内省略，避免噪声。

#### 通知与集成

- 通知（站内 / 邮件 / 短信）**走平台通用通知组件**，业务模块只定义事件
- 跨模块协作（寻源 / 合同 / 采购订单 / 价格库）通过**事件驱动**或**RPC 调用**
- FS §5 步骤表里描述跨模块调用时，写"调用 XX 模块的 YY 接口"，不展开 HTTP 细节

#### 合规与审计

- 关键操作（创建 / 修改 / 删除 / 审批 / 导出）必须有审计日志
- 数据保留期常见 5 / 7 / 10 年（视客户合规要求）
- 审批留痕（审批人、时间、意见）不可篡改

#### AI 能力的典型角色

- **辅助决策**：智能推荐、相似匹配、异常预警 — AI 不替代人工，仅给建议
- **自动生成**：报告、摘要、推荐 — 用户可修改 AI 输出
- **结构化提取**：OCR、文档解析 — 提取结果由用户复核

## 其他领域的提示

当 PRD 属于以下领域时，可参考相关通用知识临时补充：

- **ERP**：FI（财务）/ CO（控制）/ SD（销售分销）/ MM（物料管理）/ PP（生产计划）
- **MES**：工单 / 报工 / 质检 / 设备管理 / WIP 追溯
- **WMS**：入库 / 上架 / 拣货 / 出库 / 盘点 / 移库
- **CRM**：客户主数据 / 商机 / 报价 / 合同 / 售后服务

每个领域有自己的客户画像、术语表、字段命名约定。本文件不预先列出，**起草时根据 PRD 描述临时整理**。
