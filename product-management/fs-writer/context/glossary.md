# 术语表

本文件存放 fs-writer 起草 FS 时涉及的术语。

**使用原则**：
- **第 1 节**：FS 撰写本身的最基本术语（数据类型 / 触发类型 / 字段表列定义等）。这些是 skill 工作流必备词汇，固定保留
- **第 2 节**：**业务术语示例**（以 SRM 为参考）。实际起草时根据 PRD 所属领域临时增补
- **第 3 节**：使用过程中遇到 PRD 提供的新术语或澄清，**按需追加到本文件**

---

## 1. FS 撰写基本术语

### 文档体系

| 术语 | 定义 |
|---|---|
| **PRD** | 产品需求文档。上游产物，由 prd-writer 输出 |
| **FS**（Functional Spec）| 功能规格书。本 skill 的产出 |
| **功能点 / FR** | PRD 中的 FR-N.M。一份或一组紧密相关的 FR 对应一份 FS |

### FS 6 节结构

| 节号 | 节名 |
|---|---|
| §1 | 流程说明（Mermaid flowchart）|
| §2 | 功能概述（元数据表）|
| §3 | 功能界面（含 ASCII 原型）|
| §4 | 关键字段说明 |
| §5 | 功能逻辑（步骤表）|
| §6 | 数据表结构 |

可选章节（Step 3 用户主动追加才写）：§7 API 设计 / §8 测试用例

### 数据类型（业务类型枚举）

| 数据类型 | 含义 | 示例 |
|---|---|---|
| CHAR | 文本 | 编码、名称、描述、ID |
| NUM | 数字 | 金额、数量、百分比 |
| DATE | 日期 | 有效期至、创建日期 |
| DATETIME | 日期时间 | 创建时间、更新时间 |
| ACL | 下拉选择（引用其他表）| 写法："参考【表名】" |
| 勾选框 | 是/否开关 | 是否启用、是否冻结 |
| JSON | 复杂结构 | 配置快照、扩展属性 |

不使用具体 SQL 方言（如 VARCHAR / BIGINT / DECIMAL）。

### 触发类型（§5 必标其一）

| 触发类型 | 示例 |
|---|---|
| **用户操作** | 用户点击"提交"按钮 |
| **系统自动** | 状态机自动流转、级联计算 |
| **被调用** | 被上游事件触发 |
| **定时任务** | 每日 00:00 扫描、每小时刷新 |

### 编号约定

| ID | 格式 | 用途 |
|---|---|---|
| **FS_<模块>_M<NNN>** | FS_SRM_M001、FS_WAREHOUSE_M007 | FS 功能编号 |
| **TC-NNN-NN** | TC-001-01 | 测试用例编号（可选 §8）|

## 2. 业务术语示例（SRM 领域）

> 本节仅以 SRM 为示例。实际起草其他领域（ERP / WMS / MES / CRM 等）的 FS 时，**临时补充对应领域的术语**。

| 术语 | 含义 |
|---|---|
| **寻源**（Sourcing）| 采购方寻找合适供应商的过程 |
| **询价 / 比价 / 定标** | 邀请供应商报价 → 多方报价对比 → 选定中标供应商 |
| **报价底稿** | 采购方为供应商预生成的报价表单 |
| **框架协议 / 长协** | 与供应商约定一段时间内的价格与数量条款 |
| **阶梯价** | 按采购数量分档定价 |
| **BOM** | 物料清单 |
| **MOQ** | 最小起订量 |
| **含税价 / 不含税价** | 含税价 = 不含税价 × (1 + 税率) |

## 3. 用户领域术语（按需追加）

> 起草过程中如遇到 PRD 提供的新术语或对旧术语的澄清，**按以下格式追加**：

```
### <领域名>

| 术语 | 含义 | 来源 |
|---|---|---|
| <术语> | <含义> | <PRD/客户/会议纪要等> |
```

示例（当 FS 派生自 WMS PRD 时）：

```
### WMS

| 术语 | 含义 | 来源 |
|---|---|---|
| 打托 | 将多件物料组合到一个托盘上并贴标签的动作 | PRD-WMS-Pallet §2 |
| 上架 | 将物料按规则放入仓库货位 | PRD-WMS-Inbound §3 |
```

## 边界澄清

- **状态机不独立成章**：状态值在 §4 字段说明的"取值逻辑"列或独立枚举表；状态流转规则在 §5 功能逻辑的对应动作中描述
- **错误码默认嵌在 §5 步骤表**："标准业务规则"列写错误提示文案；仅 Step 3 用户追加 §7 时才单独整理错误码表
- **API 默认不写**：前后端一体化项目无需 §7 API 设计；仅 Step 3 用户追加才写
