# fs-writer

Claude Code skill：从 PRD 功能点派生 FS（功能规格书）。按"流程说明 → 功能概述 → 功能界面 → 关键字段说明 → 功能逻辑 → 数据表结构"6 节顺序，分段渐进式输出。

## 适用场景

- 已经有 PRD（产品需求文档），需要派生功能规格书（FS）给开发团队实施
- 项目采用前后端一体化开发（monorepo / 类型共享），FS 不需要写 HTTP API 契约
- 业务复杂度从简单 CRUD 到含循环重试的批处理任务，均可覆盖
- 适合 B2B / 企业级软件（ERP / SRM / MES / WMS / CRM 等）

## 安装

### 方式 1：手动安装（推荐）

1. 解压本压缩包，得到 `fs-writer/` 文件夹
2. 将 `fs-writer/` 文件夹复制到 Claude Code 的 skills 目录：

   ```bash
   # macOS / Linux
   cp -r fs-writer ~/.claude/skills/

   # Windows (PowerShell)
   Copy-Item -Recurse fs-writer $env:USERPROFILE\.claude\skills\
   ```

3. 重启 Claude Code（或新开一个对话），即可使用

### 方式 2：项目级安装

如果只想在某个项目中使用：

```bash
mkdir -p <project-dir>/.claude/skills/
cp -r fs-writer <project-dir>/.claude/skills/
```

## 验证安装

在 Claude Code 中说："写 FS" 或 "draft FS for XXX"，应当能触发本 skill。

## 使用

直接说出意图即可，例如：

- "针对【报价模板管理】功能点写一份 FS，参考 PRD-XXX.md"
- "起草 FS_SRM_M001 报价模板管理"
- "我有一份打托功能的需求，帮我写成 FS"

Skill 会按"分段渐进式"流程引导你：

1. **Step 0**：确认 FS 覆盖哪些功能点
2. **Step 1**：写 §1 流程说明 + §2 功能概述 + §3 功能界面（前半段）
3. **Step 2**：审阅通过后写 §4 关键字段说明 + §5 功能逻辑 + §6 数据表结构（后半段）
4. **Step 3**：询问是否追加 §7 API 设计 / §8 测试用例（默认不追加）

## 6 节模板结构

| 节 | 内容 |
|---|---|
| §1 流程说明 | 用 Mermaid flowchart 画业务流程，多流程画多图 |
| §2 功能概述 | 元数据表：功能菜单 / 功能编号 / 所属模块 / 功能描述 / 前置条件 / 关联功能 |
| §3 功能界面 | 主界面 + 子界面（弹窗/对话框），含 ASCII 简单原型 |
| §4 关键字段说明 | 字段表（中英双写）+ 枚举值定义独立成表 |
| §5 功能逻辑 | 按业务动作分组的执行步骤表 + 4 种复杂逻辑表达手段（决策表 / 分支流程图 / 异常清单 / 算法说明）|
| §6 数据表结构 | 每张表一节，字段中英双写，数据类型使用业务类型（CHAR/NUM/DATE/ACL/勾选框/JSON）|

## 复杂逻辑表达手段（§5.3）

简单 CRUD 用步骤表即可；遇到复杂逻辑，按需追加：

| 动作复杂度 | 推荐手段 |
|---|---|
| 含 3+ 条件组合 | 决策表 |
| 含分叉与异常路径 | 分支流程图（Mermaid）|
| 需完整覆盖异常 | 异常清单表 |
| 含循环 / 重试 / 复杂算法 | 算法说明 |

## 核心写作规范

- **字段名中英双写**：业务可读 + 开发精确
- **数据类型用业务类型**：CHAR / NUM / DATE / ACL / 勾选框 / JSON（不用 VARCHAR/BIGINT/DECIMAL）
- **枚举值独立成表**：≥3 个固定选项必须独立，不内嵌取值逻辑
- **一个按钮一个段落**：不同按钮 / 不同对象不能混
- **触发按钮名要具化**：用"确认发布"、"过账"等用户感知的按钮名
- **"标准业务规则"列必须是完整中文句**：不写 SQL 赋值表达式
- **触发类型必标注**：用户操作 / 系统自动 / 被调用 / 定时任务，四类覆盖
